# Rookfall — как это устроено

Внутренности проекта: пакеты, детерминизм, команды репозитория и все игровые решения.
Если ты просто хочешь поиграть или поднять игру локально — [README.md](../README.md).

## Команды

| Команда | Что делает |
|---|---|
| `pnpm test` | все тесты (детерминизм симуляции, реплеи, боты, протокол, сервер) |
| `pnpm test:determinism` | только детерминизм-тесты (sim + ai) — аналог CI-джоба из PRD §7.8 |
| `pnpm bench` | бенчмарк тика: 600+ юнитов на карте 128×128 |
| `pnpm e2e` | e2e в headless Chrome: поднимает сервер и клиент, играет скирмиш и матч 2 игрока + бот в двух вкладках (лобби по ссылке, чат, lockstep, выбывание, реплей). Скриншоты в `data/e2e/` |
| `pnpm typecheck` | проверка типов всех пакетов |
| `pnpm build && pnpm start` | продакшен-сборка; сервер раздаёт клиент сам на :8080 |
| `pnpm gen-maps` | перегенерировать официальные карты в `packages/sim/src/maps.generated.ts` |
| `pnpm assets` | собрать модели из ассет-пака и из `models/custom` в `packages/client/public/models` (папка в .gitignore) — см. «Конвейер моделей»; после добавления модели в `models.ts` — дописать в `scripts/copy-models.mjs` |
| `blender --background --python scripts/blender/units.py -- --out models/custom` | пересобрать модели юнитов (рабочий, солдат, лучник, ополченец, конница — по одной на эпоху): кладёт `.glb` для игры и `.blend` для ручной правки, с `--render <путь>` рендерит превью-шеренгу, с `--only Soldier` — только один юнит |
| `blender --background --python scripts/blender/catapult.py -- --out models/custom` | то же для катапульты; `--pose 1.4` рендерит её в крайней точке взмаха |

Переменные окружения сервера: `PORT` (8080), `DATA_DIR` (`./data`, сюда пишутся реплеи и `profiles.json` с рейтингами), `GIT_SHA` (версия сборки, отдаётся в `/api/health`).

## Структура

```

  sim/       @rookfall/sim   — симуляция: fixed-point 16.16, xoshiro PRNG, ECS на Int32Array, flow-field

  ai/        @rookfall/ai    — боты (лёгкий/средний/тяжёлый) и пять стратегий, доступных на любом уровне
                              (рывок/экономика/оборона/осада/ползучая осада): экономика, стройка, контрпики

  protocol/  @rookfall/protocol — JSON-сообщения лобби + бинарный формат команд/тиков.
  server/    @rookfall/server — Node + ws: лобби (комнаты по коду, открытые и приватные, слоты, команды, чат),

                              серверной headless-симуляцией, валидация команд, сверка хэшей, таймер реконнекта
                              5 минут, боты, сохранение реплеев в data/replays и профилей в data/profiles.json.
  client/    @rookfall/client — Vite + React (меню, лобби, HUD) + Three.js (инстансинг, процедурная анимация

```

## Ключевые решения

- **Детерминизм.** Симуляция использует только целочисленную арифметику и IEEE-точные операции (`+ - * /`, `Math.floor`, `Math.sqrt`), никакого `Math.random`/`Date.now`/`sin`. Итерация сущностей всегда по возрастанию id. Официальные карты предгенерированы в код, чтобы `Math.sin` генератора не различался между движками.
- **Lockstep.** Сервер — владелец тик-часов (20 Гц). Клиенты присылают команды, сервер валидирует их на своей симуляции, складывает в кадр тика и рассылает всем. Клиент исполняет кадр, когда он пришёл; каждые 50 тиков шлёт хэш состояния. В локальной игре команды исполняются с той же задержкой в 2 тика.
- **Реконнект.** При обрыве управление берёт лёгкий бот, в чат уходит системное сообщение с остатком времени раз в минуту, через 5 минут — выбывание. При возврате клиент получает все кадры с начала матча и догоняет симуляцию.
- **Конвейер моделей.** `pnpm assets` не копирует файлы, а пересобирает их (`scripts/copy-models.mjs`): выбрасывает UV-каналы (текстур в игре нет — цвет материала запекается в вершины), сваривает вершины, квантует позиции до 14 бит и нормали до 8 (`KHR_mesh_quantization`) и жмёт meshopt, оставляя тот вариант, который меньше после gzip. 11.7 МБ исходников → 2.1 МБ на диске и 0.88 МБ по сети против 2.6 МБ раньше. Две вещи, которые конвейер обязан сохранить, — это *имена*: пустышки `Hip`/`Shoulder` (иначе `prune` снесёт их как бесполезные листья) и имена материалов (иначе `dedup` склеит `LegA_Dark` с `LegB_Dark` — один цвет, но разные части анимации, и юнит перестанет переставлять ноги). Обе ловушки закрыты тестом `packages/client/test/models.test.ts`, который сверяет каждую собранную модель с исходником по числу треугольников, габаритам, набору материалов и пивотам. Квантованные атрибуты приходят в three как *нормализованные целые*; матрица, применённая к такому атрибуту, загнала бы все вершины в целочисленный диапазон, поэтому `deQuantize` в `game/models.ts` расширяет их до float до первой матрицы.
- **Рендер.** Один `InstancedMesh` на тип модели: все солдаты всех игроков — один draw call. Цвет игрока — через `instanceColor` и маску `teamMask` в вершинах. Анимация юнитов процедурная в шейдере по атрибуту `part` (ноги/руки/рука катапульты). Здания — glTF из пака Quaternius (CC0), юниты — свои модели из Blender (`scripts/blender/units.py` и `catapult.py`, исходники `.blend` и готовые `.glb` в `models/custom`), по одной на эпоху. Что в модели шевелится, задают имена материалов: `LegA_*`/`LegB_*` — ноги (part 1/2), `Right_*`/`Left_*` — руки с оружием и щитом (3/4), `Wheel_*` — колёса (5), `Arm_*` — метательный рычаг катапульты (6, ось `y=0.30, z=0.20` зашита в шейдере), `Tool_*`/`Load_*` — то, что в правой руке пусто́й и гружёной (7/8), `Team` — цвет игрока. Оси вращения ног и плеч приходят из самой модели — пустышками `Hip` и `Shoulder`, так что сустав двигают в Blender, а не константой в коде.
- **Ворота.** Четыре секции забора подряд по прямой — это ворота: на крайних клетках стоят башни надвратной постройки, на шве между двумя средними — сама дверь. Проход шириной в клетку (две мелкие ячейки, по половине от каждой средней клетки), и открыт он только команде владельца: у пути появляется отдельный слой проходимости на команду, а поля потоков кэшируются с ним в ключе (`Pathfinder.setGates`, `layerKey`). Команда без своих ворот ходит по общему базовому слою и делит его поля со всеми, так что в матче без заборов ничего не меняется. Ворота пересчитываются целиком, когда забор достроен или разрушен (`Simulation.updateGates`): каждый максимальный прямой отрезок забора одной команды получает одни ворота по центру, целочисленно и в фиксированном порядке обхода — сначала отрезки вдоль x, потом вдоль y, — поэтому все пиры кладут их одинаково. Если к середине отрезка примыкает боковой забор, ворота сначала пытаются съехать вдоль него до места, где стена в одну секцию толщиной. Когда такого места нет — например, игрок положил второй ряд вплотную к первому, — дверь прорезает стену насквозь: коридор идёт через все подряд идущие секции той же команды позади двери, до GATE_LENGTH слоёв. Отрезок, который уже пересечён чужим коридором, своих ворот не получает, поэтому у стены в два ряда ворота одни, а не двое. Глубже GATE_LENGTH ворот не бывает вовсе — это и отсекает попытки прорыть ход в сплошном массиве забора и вдоль торца толстой стены. Клетки коридора помечены слотами `GATE_TUNNEL + dir * 2 + side` — сторона шва нужна рендеру: такая клетка рисует не всю панель, а её половину, отвёрнутую от проёма. Целая панель заложила бы проход обратно, а если не рисовать ничего, ряд выглядит дырявым, и понять, что забор там стоит, можно только наведением. Проход открыт и на тяжёлом слое, так что катапульта и таран выезжают через свои ворота, хотя ни в один шов между зданиями не пролезают. Рендер рисует надвратную постройку один раз поперёк двух средних клеток и ещё по половине соседних (`GATE_WIDTH` = 3; те две клетки рисуют только отвёрнутую от проёма половину панели): в пакете это широкая секция стены с дверью чуть шире человека, и, сжатая в две клетки, она выглядела бы ещё уже, поэтому проём прорезается вдвое шире, а стена по бокам на столько же ужимается (`widenDoorway`) — в дверь должна въезжать катапульта. Створки вырезаются из той же модели: закрытый вариант — это открытый плюс две створки, поэтому треугольники, которых в открытом нет, и есть дверь (`doorLeaves`); каждая створка вешается на свою петлю и распахивается, когда к воротам подходит юнит команды-владельца, и затворяется за последним. Чужая команда видит ворота всегда закрытыми — ровно то, чем они для неё и являются.
- **Осада.** Таран (`UnitType.Ram`, кузница, первая эпоха) — единственный юнит с флагом `buildingsOnly`: `acquireTarget` для него отбрасывает всё, что не здание, `targetValid` сбрасывает уже захваченную цель-юнита, явный приказ «Атаковать» по человеку просто снимается, а `dealDamage` не даёт ему огрызнуться в ответ. Без этого он выигрывал открытое поле у равного золота солдат и лучников: 280 HP осадной брони держат мечи (×0.5), а сам он бьёт на 40 осадного урона, то есть ×2 по зданиям и ×1.25 по лёгкой пехоте. Скорость 1.4 никого не догоняет только если он и не пытается. Контрит его всё колющее (×1.5): лучники, башни, кастл. Бревно — часть 9 в шейдере: в отличие от рычага катапульты оно не крутится вокруг оси, а уезжает вперёд по +z, поэтому пивот ему не нужен.
- **Обзор не короче выстрела.** `Simulation.unitVision` и `buildingVision` возвращают `max(обзор, дальность + улучшение дальности)`: и туман (`updateFog`), и поиск цели (`idleOrder`, `attackMoveOrder`) берут это число, так что ни юнит, ни башня не могут выстрелить по тому, чего не видят, ни на одном уровне улучшения.
- **Стройка видна по модели.** У каждого здания три стадии — `Level1 → Level2 → Level3` из пака; готовое здание это всегда `Level3` (кастл — `Wonder_FirstAge_Level3`, башня — `WatchTower_FirstAge_Level3`). Стадия выбирается по прогрессу стройки (`buildStage`), все три масштабируются одним коэффициентом от финальной модели, так что здание растёт, а не прыгает в размере. Соответственно у зданий по три набора инстансов — `buildingSets[type][stage]`.

## Рейтинговый режим и приватные комнаты

**Рейтинг** (кнопка «Рейтинг» в меню) — 1v1 на карте `random-duel`: 64×64, катается из сида матча, базы в противоположных углах с поворотной симметрией, так что обе стороны идут друг к другу по одинаковой местности. Скорость выбирается перед поиском: `1×` обычная или `3×` турбо — у каждой своя очередь, потому что оба игрока должны согласиться на темп.

- **Рейтинг — Glicko-2** от 1500 (`packages/server/src/rating.ts`), одна партия = один рейтинговый период. Окно поиска расширяется по PRD §7.6: ±50 первые 20 с, дальше +25 каждые 10 с, потолок ±400; профиль с большим RD (первые матчи, возвращение после перерыва) пускается шире, потому что его рейтинг всё равно мало что значит. Матч отдаётся паре с самой близкой разницей, приоритет — у того, кто ждёт дольше.
- **Калибровка** — первые 5 матчей: ранг не показывается, рейтинг ходит широкими шагами (RD 350 → ~290 после первой партии).
- **Если соперника нет — играем с ботом** (митигация §12 «пустые очереди при малом онлайне»). Через `RANKED_BOT_WAIT_SEC` = 180 с окно поиска уже стоит на потолке ±400, то есть ждать дальше бессмысленно: очередь ставит бота по силе рейтинга (<1300 — лёгкий, <1700 — средний, выше — тяжёлый) и запускает матч на той же карте и скорости. В ладдер он не пишется (`Room.rankedKeys` остаётся пустым, фармить рейтинг об бота нельзя), в очереди виден обратный отсчёт, на экране результатов вместо строки рейтинга — «тренировочный матч».
- **Уровень** растёт от опыта за матчи (30 за победу, 12 за поражение, +1 за минуту до 12), полоса под рейтингом показывает прогресс до следующего.
- **Выход из живого рейтингового матча = поражение**: кнопка выхода из меню паузы сдаёт партию, а не оставляет вместо игрока бота. Обрыв связи по-прежнему работает по правилу PRD §4: бот-заглушка и 5 минут на возвращение.
- **Профиль** привязан к ключу в `localStorage` браузера (`rookfall.playerKey`) — аккаунтов ещё нет. Ключ уходит на сервер только в `hello`, наружу отдаётся публичный id профиля.
- **Локальный тест вдвоём:** матчмейкер не сводит профиль сам с собой, поэтому вторую вкладку надо открывать как `http://localhost:5173/?profile=b` — это отдельный ключ и, значит, отдельный рейтинг.

**Приватная комната** — в мультиплеере кнопка «🔒 Приватная комната»: такая комната не попадает в список открытых, зайти можно только по коду или ссылке-приглашению. Хост переключает видимость в любой момент кнопкой рядом со ссылкой.

## Отличия от PRD (по решению автора)

- **Кастл обороняется сам**: 30 колющего урона, дальность 7, перезарядка 2 с, +5 к урону за каждый уровень апгрейда «Атака дальнего боя» (у башни +2). В PRD §4.4 у кастла атаки нет.
- **Дальность оборонительных зданий считается от стен**, а не от центра клетки-якоря: атакующий мерит свою дальность до края постройки, поэтому в дальность кастла/башни добавляется полфутпринта (`Simulation.buildingRange`). Без этого кастл терял 1.5 клетки от заявленных 7 и одна катапульта могла безнаказанно его разбирать.
- **Катапульта не перестреливает кастл**: её дальность 7 — ровно как у кастла (в таблице PRD §4.5 — 8). Зажигательный снаряд бьёт на те же 7. Кастл успевает убить одинокую катапульту за ~8 с, тогда как ей нужно ~30 с на кастл; ломать базу теперь идут армией, поэтому матчи ботов длятся 20–30 минут вместо 10–20.
- **Заборы** (`Wall`, 20 золота, 250 HP, 1 клетка, 5 с) — шестой тип здания — дешёвое перекрытие проходов; осадный урон (×2 по зданиям) сносит секцию за 3 выстрела. В PRD §4.4 их нет — там ровно пять зданий. Секции сами ориентируются по соседям: прямой участок — цельная панель, угол и перекрёсток собираются из половинок к каждому соседу (`Renderer.addWall`).
- **Случайные спавны.** У каждой карты вдвое больше точек старта, чем слотов: по две «кандидатки» на зону (`MapStart.zone`), симуляция перемешивает зоны и берёт случайную кандидатку из каждой (`Simulation.pickStarts`, по seed матча — детерминированно). Игроки всегда в разных зонах, то есть на прежнем расстоянии друг от друга; шахта базы стоит между двумя кандидатками зоны. В PRD старты фиксированные.
- **Стройка только на разведанном.** Ставить здание на неразведанную клетку нельзя (отказ `unexplored`), а площадка даёт обзор лишь после того, как по ней поработал рабочий (`Simulation.updateFog`). Иначе постановка забора за 20 золота была бы самой дешёвой разведкой в игре.
- **Рабочие сами находят работу.** Свободный рабочий сначала достраивает недостроенное (пока на стройке меньше трёх), затем чинит повреждённое, и только потом идёт за золотом (`systems/workers.ts`). Раз в 10 тиков диспетчер раздаёт задачи простаивающим и снимает с золота одного ближайшего добытчика на стройку, у которой никого нет, или на здание, которое никто не чинит (не больше двух за раз). Явные приказы игрока не трогаются: рабочий после Stop стоит, пока не появится стройка или починка.
- **Случайная карта** (`random`, 96×96, до 4 игроков и `random-duel`, 64×64, 1v1 — на ней играет рейтинг) генерируется из seed матча на каждом пире: угловые зоны (на четверых — зеркальные по обеим осям, на двоих — поворот на пол-оборота), жила у каждой базы, зеркальные экспанды, богатый центр, случайные пруды, леса и скалы, прорубленные коридоры от каждого старта к центру. Только целочисленная математика и seeded PRNG — никаких `sin`/`cos`/`hypot`, чьи младшие биты различаются между движками (`generateRandomMap`).
- **Лес горит.** Зажигательный снаряд поджигает лесные клетки в радиусе зоны; через 8 с они выгорают в проходимую землю (`Simulation.igniteForest`), деревья исчезают, на карте остаётся гарь. У симуляции своя копия тайлов — кэш официальных карт не портится.
- **Здания ставятся вплотную, между ними шов для пехоты.** Обязательного прохода в клетку между зданиями больше нет — только вокруг золотых жил. Сетка пути вдвое мельче клетки карты (`Pathfinder`, `SUB = 2`): у двух соседних футпринтов внешние полуклетки, обращённые друг к другу, открыты для обычных юнитов — получается шов шириной в клетку, по которому пехота, рабочие и конница просачиваются между домами. Тяжёлый слой (катапульта) держит полные футпринты, для неё шва нет. Забор швов не открывает — дом, поставленный вплотную к забору, наглухо закрыт. Но забор, вставший поперёк уже открытого шва, его не затыкает: коридор прорезает подряд идущие чужие футпринты на своём пути и выходит наружу (`Pathfinder.seamOpen`, до `SEAM_TUNNEL` = 4 клеток вглубь — это накрывает любую стену, в которую влезают ворота, и не даёт шву расстегнуть длинную двойную линию забора вдоль). Иначе ряд башен, поставленный вплотную за линией забора, оставлял бы между башнями слепой карман: шов есть, а выйти из него некуда. Тяжёлый слой больше не расширяется на клетку, поэтому катапульта проезжает в любой проход шириной в клетку — между домами, между деревьями, в разрыв забора.
- **Скорость матча 1×/2×/3×/5×** выбирается при создании игры (скирмиш и лобби, `MatchSetup.speed`). Меняется только частота тиков реального времени (`tickMsFor`) — симуляция, реплеи и хэши те же; в HUD горит значок «5×».
- **Хоткеи по физической клавише.** Привязки читаются из `KeyboardEvent.code`, так что на русской раскладке «Ф» — это по-прежнему A. Стрелки двигают камеру наравне с WASD. Клавиша режима, совпадающая со скроллом (A = атака-движение и скролл влево), удержанная две секунды, считается скроллом: режим снимается, автоповтор клавиши приказов не дублирует.
- **Точка сбора как первое задание.** Если точку сбора кастла поставить на стройку — новые рабочие идут строить, на шахту с местом — заходят внутрь, на повреждённое здание — чинят, на жилу — добывают; клик по зданию/жиле прилипает к нему. Когда там уже нечего делать, рабочий выбирает работу сам.
- **Недостроенное здание не мешает ходить.** Футпринт закрывается для пути только в момент достройки; чтобы на площадку не поставили другое здание, пересечение проверяется отдельно в `canPlaceBuilding`.
- **Явный приказ добывать — закон.** Диспетчер снимает с золота только тех рабочих, которые пошли добывать сами (`GATHER_AUTO`); рабочего, отправленного на жилу игроком, он не тронет.
- **Встречное движение.** Два юнита, идущие навстречу, получают боковой толчок по одному правилу правой руки с обеих сторон — расходятся, а не толкаются лбами вечно (`resolveMovement`).
- **Гружёный рабочий медленнее и с золотом в руках.** Полная ходка (`GOLD_PER_TRIP` = 8) замедляет рабочего на `LOADED_SLOW_PCT` = 30 % на обратном пути к кастлу (`Simulation.unitSpeed`) — остатки выработанной жилы он доносит на полной скорости. Видно это и по модели: кирка из рук пропадает, а вместо неё в обеих руках появляется гора самородков. Кирка и гора — это части `Tool` и `Load` одной модели, шейдер по инстанс-атрибуту `aAnim.z` показывает ровно одну (вторая схлопывается в точку) и заодно перестаёт качать обе руки: гружёный рабочий держит ношу перед собой, а не размахивает ей. Так обходимся без второй модели рабочего и лишнего инстанс-сета. С ношей он ничем другим и не занимается: любой новый приказ — от игрока, бота или диспетчера — встаёт в очередь, рабочий сначала доносит золото до кастла (`Simulation.setOrder` подменяет приказ доставкой, `gatherOrder` запускает отложенное сразу после сдачи), и недобранный остаток тоже сдаёт, а не таскает с собой. Исключение — «Стоп» и «Держать позицию»: это не работа, а отзыв, они исполняются сразу. Диспетчер гружёного рабочего вообще не трогает. В PRD ноша ни на скорость, ни на приказы не влияет.
- **Две эпохи: деревянная и каменная.** В PRD эпох нет. Исследование «Вторая эпоха» (`CommandType.AgeUp`, кнопка 🏛️ в панели кастла, 500 золота, 60 с, нужна кузница) ставится в очередь кастла как апгрейд. По завершении все здания игрока — достроенные и площадки — становятся каменными: модели пака `*_SecondAge_*` (модели, инстанс-сеты и призраки в тумане индексируются `[эпоха][тип][стадия]`), максимальное HP ×1.3 с сохранением доли повреждений (`AGE_BUILDING_HP_PCT`). Эпоха открывает катапульту и конницу (`UnitDef.age`) и уровни улучшений выше первого (`UPGRADE_MAX_LEVEL_BY_AGE`); отказ `age` показывается подсказкой «нужна вторая эпоха». Значок I/II в панели ресурсов, тост о переходе видят все. Боты переходят в эпоху, как только стоит кузница и хватает золота; средний и тяжёлый ставят собственную шахту и заводят в неё простаивающих рабочих, а конницу учитывают в контрпиках (солдаты против конницы, конница против катапульт и лучников). Эпоха входит в хэш состояния.
- **Гарнизон башни.** В сторожевую башню, как и в шахту, заходят до трёх рабочих (ПКМ рабочими по башне, `garrisonCapacity`); каждый добавляет выстрелу `TOWER_GARRISON_DAMAGE` = 8 урона (башня 15 → 39 с полным гарнизоном), считается в населении. Когда башню разрушают, рабочие выпадают наружу и каждый с шансом 50 % (`TOWER_FALL_DEATH_PCT`, бросок на rng матча) погибает под обломками; при разборке своей башни выходят целыми. Подсказка в панели, кнопка «Выпустить».
- **Башня поверх забора.** Башню можно поставить прямо на свой (или союзный) забор: клетки забора под футпринтом поглощаются при закладке (без возврата 20 золота), всё остальное под башней по‑прежнему запрещено. Рендер считает клетки башни частью линии, поэтому соседние секции забора примыкают к ней без зазора.
- **Вторая эпоха в бою и на виду.** Замок бьёт на +10 (`BuildingDef.ageDamage`), башня на +4; в панели урон показан с учётом эпохи, улучшений и гарнизона. У всех юнитов второй эпохи железные доспехи (`Models.units[эпоха][тип]` — отдельная модель на эпоху: наплечники у солдат и ополчения, кираса у лучников, бард на коне, железные оковки и колёса в стальных шинах у катапульты), а у рабочего вместо соломенной шляпы — фетровая с лентой цвета команды и пером. В русской локализации кастл переименован в замок.
- **Рабочий разбирает свои здания.** Кнопка «Разобрать» (🪓, `X`) у выделенных рабочих переводит курсор в режим цели: клик по своему или союзному достроенному зданию — и рабочие идут к нему и «раскручивают» прогресс стройки назад (`Order.Dismantle`, `CommandType.Dismantle`). Скорость — 150 % от скорости стройки того же числа рабочих (`DISMANTLE_SPEED_PCT`): ломать не строить. Модель проходит стадии Level3→2→1 в обратном порядке, кольцо показывает остаток, в панели — «Разбирается N %»; на нуле здание исчезает без боевой потери и без возврата золота, рабочих из шахты выпускают наружу. Площадку разобрать нельзя — у неё своя кнопка отмены с возвратом; последний кастл игрока — тоже (отказ `lastCastle`), иначе рабочий мог бы устроить самоликвидацию.
- **Рендер:** земля — общая сетка вершин с цветами, смешанными по четырём соседним клеткам, плюс медленный шум на клетках и мелкий шум в шейдере — без «пиксельных» квадратов; у выделенного идущего юнита (и у всех только что получивших приказ) рисуется полупрозрачный пунктирный маршрут по реальному полю пути (у рендера своя копия pathfinder'а, бюджет симуляции не тратится); кольцо дальности приглушено до 30% непрозрачности; у зданий нет полоски вовсе: одно кольцо показывает прогресс стройки (золотое), а потом здоровье — зелёное выше половины, оранжевое до 35 %, красное ниже; полупрозрачное у повреждённого или недостроенного, полноцветное у выделенного; кнопка ⛶ в HUD и меню — полный экран; зажатая ПКМ таскает камеру по карте так же, как средняя кнопка (порог 8 px: короткий клик остаётся умным приказом, перетаскивание — скроллом; отключается в настройках), а обе кнопки сразу — то же самое вдвое быстрее и без приказа на отпускании. Камера вращается только с Q/E: крутить её мышью в матче, где север всегда сверху на миникарте, только сбивало прицел.
- **Недостижимая цель — ближайшая достижимая.** Клик в воду, в глубь леса или за забор больше не заставляет юнита упираться: pathfinder помечает связные области (`Pathfinder.nearestReachable`), и юнит идёт к ближайшей клетке своей области, а рабочий, чья жила отгорожена, бросает её и берёт другую работу. Клик в непроходимое ведёт к его краю (кольцо посева расширено с 3 до 12 клеток), а при исчерпании бюджета полей за тик юнит ждёт тик, а не идёт по прямой в препятствие. Бюджет полей 6 → 12 за тик, кэш 64 → 128.
- **Между зданиями всегда проход, но не для катапульты.** Здания ставятся не ближе чем через одну клетку друг от друга (заборы могут касаться чего угодно), так что пехота проходит между ними, а катапульта ходит по «раздутой» карте проходимости (`Pathfinder.blockedHeavy`: клетка закрыта, если закрыт любой сосед) и в проход шириной в клетку не лезет.
- **Рабочие сами идут в шахты.** После стройки и починки свободный рабочий (в том числе только что нанятый без точки сбора) занимает своё место в шахте, где есть место, и только потом идёт за золотом. Выведенные из шахты кнопкой назад не идут.
- **Конница.** Пятый юнит казармы: копейщик на коне — 120 золота, 3 населения, 130 HP, 14 колющего, лёгкая броня, скорость 3.9 (солдат 2.4), хоткей `V`. Быстрый рейдер: ×1.5 по катапультам, но солдаты режут его ×1.5. Бот учитывает конницу в контрпиках и строит её со второй эпохи.
- **Забор тянется линией.** В режиме постройки забора ЛКМ зажимается и протягивается: линия привязывается к длинной оси, каждая клетка подсвечена зелёным/красным, ставится столько секций, на сколько хватает золота (первая — сразу, остальные в очередь рабочего; Shift не сбрасывает инструмент). Диспетчер рабочих учитывает очередь приказов (её длина поднята с 6 до 16), чтобы не считать хвост линии «брошенной стройкой», и никогда не снимает с золота больше половины рабочих.
- **Население считается на выходе.** Юнит попадает в счётчик населения, когда выходит из здания, а не при постановке в очередь; заказывать можно и при полном лимите. Готовый юнит, которому нет места, ждёт внутри — над зданием мигает красный значок, в панели подсказка; как только лимит вырос (достроен дом), выходит на следующем тике. Бот для планирования по-прежнему считает свою очередь.
- **Награда за фраг.** За убитого вражеского юнита убийца получает 1/10 его цены (`KILL_BOUNTY_DIV`); ополчение бесплатное — за него ничего.
- **Шахта** (`BuildingType.Mine`, 150 золота, 30 с, 500 HP, 2×2) — пассивный доход от рабочих внутри: до трёх, по `MINE_GOLD_PER_WORKER` каждые 5 с на каждого (≈48/мин на рабочего против ≈80/мин у добытчика на близкой жиле, зато без ходьбы и вне боя). ПКМ рабочими по своей шахте — зайти; кнопка «Вывести» — выйти. Рабочие внутри не сущности, но считаются в населении. При работающей шахте из неё летят монеты, над пустой мигает красная фигурка (только своей команде). Нейтральная залежь для отличия переименована в «золотую жилу».
- **Зажигательный снаряд летит.** Раньше зона огня появлялась мгновенно; теперь это снаряд, который 0.6 с ждёт в ковше (катапульта разворачивается, рука взмахивает), летит с огненным шлейфом и поджигает землю в точке падения (`systems/projectiles.ts`). Сама катапульта развёрнута: рука сзади, бросок вперёд — раньше она ездила ковшом вперёд и кидала назад.
- **Удар по стройке откатывает её.** Урон по недостроенному зданию снимает и прогресс (hp и прогресс во время стройки — одна величина, `constructionProgressForHp`), а строители на 3 с работают на 35% медленнее (`SITE_HIT_SLOW_*`). В HUD выделенная площадка под обстрелом показывает таймер.
- **У ботов одного уровня разные стратегии.** Сложность говорит, насколько хорошо бот играет (как часто думает, сколько приказов успевает, микрит ли, разведывает ли), а стратегия — во что: она разыгрывается из сида матча на каждого бота отдельно (`Strategy`, `PLANS`), поэтому два бота одного уровня в одной партии открываются по-разному и к середине игры у них видимо разные базы. **Рывок** (`Rush`) — казарма на четырёх рабочих, вторая уже на 180 золота, ни одной башни, точка сбора вынесена вперёд; идёт не в кастл, а на дальнюю жилу противника: пять человек перед кастлом просто умирают (30 урона, дальность 7), а каждый убитый добытчик — это золото, которое не пришло. **Экономика** (`Boom`) — своя шахта раньше военного, второй кастл с четвёртой минуты, дома на десять населения вперёд и пять казарм; копит до половины лимита населения и выходит всем сразу. **Оборона** (`Fortify`) — обносит базу забором, ставит башни у ворот, заводит в них рабочих под обстрелом (три рабочих поднимают выстрел башни с 15 до 39) и держит армию у кастла, пока стена не встала. **Осада** (`Siege`) — кузница раньше второй казармы, первым копит на вторую эпоху и давит катапультами. **Ползучая осада** (`Creep`) — копит и ведёт на противника линию башен, каждая следующая в пяти клетках от предыдущей, то есть внутри её семиклеточной дальности; армия ждёт у передовой башни, потому что без охраны рабочих на стройке убьют. Линия ровно такой длины, какой хватает дойти (`wantedTowers`), иначе бот покупал бы башни вместо армии, которой заканчивать.
- **Уровень — это мастерство, а не список разрешённых построек.** Раньше у лёгкого профиля стояли флаги `towers: false` и `expand: false`, то есть половина стратегий ему была недоступна. Теперь в профиле только мастерство (интервал раздумий, APM, микро, разведка, улучшения, реакция), а что строить — дело плана, и **все стратегии доступны на всех уровнях**: лёгкий «оборонщик» действительно обносит себя забором, просто медленнее, меньшей армией и без микро. Масштаб задаёт одно число профиля — `ambitionPct` (45/100/130): сколько бот успевает от аппетита своего плана по замкам, шахтам, казармам и башням. На одинаковом плане лестница уровней осталась: `d2 vs d1` 17-5, `d1 vs d0` 25-0.
- **У бота нет своего лимита на юнитов.** Потолок у бота ровно тот же, что у игрока, — `MAX_POP`, и никакого второго потолка «для ботов» в профиле больше нет (поле `maxWorkers` убрано). Сколько бот держит рабочих — это выбор плана, как у игрока: `workerPct` задаёт долю лимита населения на добычу (18 % у рывка, 30 % у экономики), а сверху её режет только то, сколько работы реально есть — жилы рядом и свои шахты. Дома он строит, пока лимит не упрётся в тот же `MAX_POP`. Уровень сложности на численность не влияет вовсе: он про мастерство и про `ambitionPct` (сколько построек бот успевает), а не про то, сколько ему разрешено юнитов.
- **Ограничений на стройку нет — есть цена.** Бот может взять сколько угодно замков (хоть всю карту), несколько шахт на каждый, сколько угодно башен и казарм; счётчик в плане — это аппетит, а не потолок. Останавливает его `copyPrice`: каждая следующая копия здания требует на `COPY_SURCHARGE` = 190 золота больше свободных денег, чем предыдущая (надбавка начинается с третьей — вторая казарма или второй замок это обычный рост). Без этого жадные планы покупали восемь замков и пять казарм, которые нечем было заполнить, и проигрывали планам, которые просто строили солдат. Отдельно важны **шахты**: это единственный доход, который не кончается — три рабочих внутри платят и после того, как жилы вокруг базы выработаны, — поэтому план, который держит большую армию, копает их по две-три на замок, а не одну.
- **Башни ставятся на фронт, а не по кругу.** Аппетит на башни растёт с числом замков (`wantedTowers`), и почти весь он тратится на сторону, откуда ходит враг: `frontTowerSpot` перебирает сектор, повёрнутый к слабому месту противника, и берёт первое подходящее место ближе к центру сектора, поэтому повторные вызовы уплотняют фронт, а тыл остаётся голым. У плана с забором башни идут в ногу со стеной (по одной на каждые 8 секций) и встают сбоку от ворот: прямо за дверью башня была бы затычкой, а не охраной.
- **Забор ставят почти все планы, вопрос только когда.** Раньше кольцо строил один план из пяти, и игрок видел забор примерно у каждого пятого бота — то есть почти никогда. Теперь у каждого плана два числа: `wallSides` — сколько сторон кольца он готов оплатить в порядке угрозы (сторона врага → фланги → тыл), и `wallAfter` — с какого тика он вообще возьмётся за кладку. Оборона берёт четыре стороны с первой минуты, потому что это её план. Рывок тоже обносит себя целиком, но с девятой: пока идёт его пуш, у опенинг-золота есть занятия получше камня. Ползучая осада — четыре стороны с пятой минуты. Массирующий и осадный планы — это тоже пуш, только поздний: им достаётся две стороны и десятая-девятая минута, потому что кольцо, начатое раньше, съедало ровно ту волну и ту эпоху, ради которых план и существует (замер: у массирующего 26 побед из 48 против 7, когда он строил полное кольцо с восьмой минуты). Любому из них два визита врага к базе (`REACTIVE_WALL_ATTACKS`, счётчик эпизодов в `detectThreat`) отменяют отсрочку: один прохожий не повод, два раза подряд — уже повод перегородить дорогу. По замеру на 24 ботах со случайным роллом стратегий: было 3 из 24 с забором, стало 17–18 из 24.
- **Забор не трогает то, на что копят.** Копит бот всегда на что-то одно (`savingFor`), и кольцо из этих денег не строится: пока идёт накопление, линия не останавливается, а сужается до одной секции за раз и берёт только то, что выше отложенного плюс `WALL_SAVING_MARGIN`. Обе крайности проверены и обе плохи: если дать полной бригаде тратить во время накопления, осадный план заканчивает партию с забором и без второй эпохи — то есть без осады; если остановить линию совсем, большинство ботов не строят забор вообще, ради чего всё и затевалось. Целью накопления забор считается только у того плана, который с первой минуты планирует город.
- **Внутри стен — улицы.** Обнести базу мало: из неё надо выходить. Симуляция ставит ворота в середине каждого достроенного отрезка, значит место ворот известно ещё до того, как встала стена, и бот, который планирует город с первой минуты, держит от середины каждой стороны к центру базы свободную полосу (`onRoad`, `ROAD_HALF`): постройки на неё не садятся. Ширина взята по катапульте — пехотинец пролезет и в шов между двумя зданиями, осадная машина нет. Проверено на всех обнесённых базах в реальных матчах: и пехота, и катапульта доходят от замка до центра карты (`Pathfinder.reachable` по слою своей команды).
- **Забор бота — это кольцо с воротами.** Прямоугольник рисуется один раз (`planWall`) вокруг всего, что к тому моменту стоит, плюс запас на вырост, и раздвигается наружу, пока ни одна сторона не идёт вплотную к жиле: залежь держит клетку-полосу, которая забор не принимает, а дыра в кольце хуже кольца на клетку шире. Дальше бот кладёт секции курсором по кольцу в порядке «сторона, на которой живёт враг → фланги → тыл», очередью приказов на одном рабочем — ровно так, как игрок протягивает линию мышью (и по той же причине эти приказы не считаются в лимит APM: для игрока это один жест). Четыре достроенные секции подряд симуляция превращает в ворота, поэтому выход из собственной стены получается сам собой — у закрытого кольца их 3–6, и катапульта в них проходит. Пока кольцо не закрыто, всё, кроме нового кастла, бот строит внутри него (`findSpot`); когда курсор доходит до конца, кольцо обходится заново раз в 45 с — так зарастает пролом. На 11 стартах из 14 кольцо к 16-й минуте стоит целиком (28–59 секций).
- **Бот щупает оборону со всех сторон.** `weakApproach` ставит двенадцать точек по кругу вокруг центра вражеской базы и считает для каждой, что будет по ней стрелять: кастл и башня весят много, забор мало (забор — это задержка, а кастл — это бой), видимые войска посередине. Неразведанная земля стоит дёшево нарочно: не знать, что там, — повод сходить посмотреть, и только так бот вообще находит сторону, которую никто не охраняет. Дальше идёт длина пути (обходить базу кругом дороже башни, которую обходишь) и небольшая фора стороне, которую бот уже выбрал, — иначе он менял бы направление каждые несколько секунд и никуда не доходил. Точка используется и волной (подходит с тонкой стороны и только там выбирает цель), и ползучей линией башен. Если тонкой стороны нет вовсе — база сильна со всех сторон (`FORTRESS_SCORE`), — бот не лезет в неё, а берёт то, что за стены не спрячешь: дальний замок, шахту у крайней жилы и рабочих на ней. Никакой тригонометрии: направления берутся из таблицы целочисленных векторов `DIRS`, потому что `Math.sin`/`atan2` не обязаны совпадать между движками, а команды ботов должны быть одинаковыми у всех пиров.
- **Забор ломают в одном месте.** Волна не разбирает стену по секциям: если до цели не дойти (`Pathfinder.reachableFP` по слою своей команды), бот выбирает одну секцию между собой и целью, наводит на неё всё, что бьёт по зданиям (включая тараны — по забору они не работают, кроме этой секции), и **прекращает, как только проход открылся**. Дальше — обычные приказы, а значит сначала люди: `acquireTarget` предпочитает юнитов зданиям, и волна внутри базы добивает гарнизон, прежде чем браться за постройки. По замерам атакующий сносит 0–3 секции забора за партию вместо всей линии.
- **Бот копит на что-то одно.** Забор, второй кастл и вторая эпоха — три вещи, на которые нужно отложить, и пока бот копил на все сразу, он не получал ничего: очереди казарм съедали монету в тот же тик, когда она падала, забор тратил то, что ждал кастл, а бот, обносивший стеной одну базу против соперника с двумя, проигрывал ту самую партию, которую защищал. Теперь `savingFor` выбирает одну цель за раз, и только она держит резерв, которого очереди не касаются; сама покупка из своего же резерва не платит. Порядок зависит от плана: у осадного эпоха идёт впереди кастла (катапультный план в деревянной эпохе не план), у планa с забором второй замок идёт впереди кольца, а третий — уже после него. Видно это прямо в партии: боты доходят до второй эпохи, а с ней до катапульт, конницы и каменных стен.
- **Индикатор дальности**: у выделенных дальнобойных юнитов и оборонительных зданий рисуется белое кольцо радиуса атаки (у катапульты ещё тусклое кольцо минимальной дальности); при установке башни кольцо показывается вокруг призрака.
